## 1. Unparseable frontmatter grants every tool

`frontmatter.parse` (`src/tara/frontmatter.py:44-49`) returns an empty mapping when the YAML fails to parse.
The Claude translator (`src/tara/claude.py:163`) then omits `tools`, and the OpenCode translator (`src/tara/opencode.py:112-117`) omits `permission`, so the agent inherits every tool.
An unquoted colon in a description, such as `description: Reviewer. Use when: reviewing diffs`, is enough to trigger it.
The parser on main still read `tools` from this kind of file, so this is a regression.
The fix is to fail closed: skip and report the file, or emit the safe tool set and deny everything else.

## 2. `--version` uses the wrong distribution name

`src/tara/cli.py:70` calls `package_version("tara")`.
After runbook step 12 renames the distribution to `tara-dev`, this raises `PackageNotFoundError`, or prints the version of an unrelated package called `tara` if one is installed.
The fix is to look up `tara-dev`, or to resolve the distribution through `importlib.metadata.packages_distributions()`.

## 3. Multi-line lists corrupt `config.toml`

`_replace_artifacts_table` (`src/tara/config.py:272-305`) drops only `key = ...` lines and keeps the continuation lines of a list that spans several lines.
The resulting file fails to parse, and every command that loads the config fails until the file is fixed by hand.
Formatters such as taplo write long lists this way.
The fix is to parse the file, update the data and write the whole file again, or to use `tomlkit` to keep the formatting.

## 4. 1.x configs skip artifact discovery

`_rebuild_manifest` only discovers existing catalog items when `cfg.artifacts is None`.
`write_config` (`src/tara/config.py:229`) adds an empty `[artifacts]` table, and `record_artifacts` (`src/tara/config.py:309-318`) writes only the new item, so after `tara integrations` or `tara add` the discovery never runs.
The fix is to leave `[artifacts]` out in `write_config` when it is missing, and to run discovery first in `record_artifacts` when `cfg.artifacts is None`.

## 5. OpenCode port replaces user keys

`port_config` (`src/tara/opencode.py:169-172`) always replaces `instructions`, `mcp` and `$schema`, without asking and ignoring `force`.
`_remove_config` (`src/tara/opencode.py:268-286`) removes those keys and deletes the file when it is empty.
A user's own MCP server or instruction entries are lost.
The fix is to record which values Tara wrote, merge into the existing keys, ask before changing values Tara did not write, and only remove recorded values.
This belongs with #30.

## 6. `--tool all` now includes Claude

`normalize_integrations` (`src/tara/core.py:60`) expands `all` to every integration, including `claude`, while the config loader keeps the 1.0 meaning of copilot plus opencode.
A script that runs `tara init --tool all` now gets `CLAUDE.md` and `.claude/`.
The fix is to map `--tool all` to copilot and opencode, or to list the change under breaking changes in the changelog.

## 7. Remaining containment gaps

`generate.record` (`src/tara/generate.py:221-224`), `sync.write_lock` (`src/tara/sync.py:203-207`), `src/tara/skills.py:121` and `src/tara/skills.py:136`, and `src/tara/docs.py:149` do not call `unsafe_reason`.
If `.tara` is a symlink, `generated.json` and the lockfiles are written outside the repository.

## Known gaps, confirmed

- `core._write` (`src/tara/core.py:152-158`) overwrites `copilot-instructions.md` and `.mcp.json` during `init` without an ownership or containment check.
- `agent_docs.py:108` and `agent_docs.py:132`, `standards.py:87`, `config.py:241` and `config.py:316`, and `cli._scaffold` (`cli.py:1056`) have no containment check.
- `catalog.install_item` checks containment but still replaces existing skills and files without asking (`catalog.py:268`, `catalog.py:305`). This is #30.
