# Runbook: execute the 2.0.0 release blockers

## Trigger

Use this runbook to close the 2.0.0 milestone and publish `tara-dev` 2.0.0.
The tracking issue is #33.
Run it with `/runbook .agents/plan/202610041800_release-2.0.0-execution-runbook.md`, one step per session or per review round.

## Prerequisites

- Read `.github/copilot-instructions.md`, `.agents/plan/202610021025_stable-release-roadmap.md`, and the issue named in the step.
- Tools: `uv`, `gh`, `git`.
- `uv run tara check` is the gate. Run it after every step.

## Rules for every step

- Write the failing test first, then the minimum code to pass it.
- Keep each step to one logical change, and touch only the files the step needs.
- Never commit, push, merge, tag, or publish. Stage the files with `git add`, draft the commit subject, and stop.
- Stop at every **Review stop**. A clean agent with fresh context, preferably on a different model than the implementer, reviews the staged diff with the `/review` prompt and files the result in `.agents/review/`.
  The implementer never reviews its own work. The developer reads the review and commits.
- Never overwrite or delete a file Tara did not generate. Use the helpers in `src/tara/generate.py`.
- Keep the CLI and config backward compatible. Old flags and keys keep working as aliases.
- Add a line to `CHANGELOG.md` under `[Unreleased]` for every user-facing change.
- Markdown: one sentence per line, no em dashes.
- If a step is blocked or the issue is unclear, stop and report. Do not guess.
- After each step, record the result, the decisions, and anything left open in a hand-off note in `.agents/memory/`.

Steps marked (developer) push, merge, publish, or change repository settings.
The agent prepares them and stops.

## Steps

### 1. Contain generated paths and fix the failing tests (#20, #49)

Branch: `feat/claude-code-support` (PR #17).

1. Run `uv run pytest -q` and record the failing tests.
2. Add one containment helper in `src/tara/generate.py`. It rejects a destination when any ancestor below the repository root is a symlink, or when the resolved path is outside the resolved root.
3. Use the helper for every write, copy, unlink, and recursive delete in `generate.py`, `hooks.py`, the catalog installer, and the Claude and OpenCode adapters. Remove the per-adapter checks it replaces.
4. Add regression tests for symlinked Claude agent, command, and skill parents, and for the OpenCode equivalents.
5. For `test_merge_does_not_deduplicate_across_different_matchers` and `test_merge_appends_only_missing_actions_for_the_same_matcher`, decide whether the code or the test is wrong, and write the reason in the hand-off note.
6. Run `uv run tara check` until it passes. Do not skip or xfail tests.
7. Stage and draft: `fix: contain generated paths within the repository`.

**Review stop.**

### 2. (developer) Land PR #17

1. Done: the merge of `main`, step 1, and the runbooks feature are committed on `feat/claude-code-support`.
2. (developer) Commit the open `.agents/` changes (reviews, drafts, and this runbook) with `docs: add PR #17 reviews and update the 2.0.0 runbook`, then push.
3. (developer) Merge PR #17 after review and green CI.
4. (developer) Create `fix/stable-2.0.0-blockers` from the updated `main`. Steps 3 to 11 run on this branch, one commit per issue.

### 3. Harden the review flow and ship the lessons learned

No issue.
The PR #17 reviews showed that a self-check and diff-only reviews miss duplication across the codebase, fail-open parsing, and project invariants.
Every lesson an agent stores as a memory also belongs in Tara's bundled content, so the harness prevents the same mistake for every user.

1. `src/tara/data/catalog/prompts/review.prompt.md`:
   - The review runs in a clean agent with fresh context, preferably a different model than the implementer, and never by the agent that wrote the change.
   - For every new parser, writer, path constant, or error type, search the whole codebase for an existing one and report duplicates.
   - Feed every new parser malformed and hostile input, and check that permission-relevant parsing fails closed.
   - Read the project's invariants, if the repository has them, and check each one.
2. `src/tara/data/instructions/base.md`: add a review step to the workflow between Check and Document that runs `/review` in a clean agent, and update the Definition of Done to require a filed review.
3. Add the missing lessons to the bundled content they belong to, one directive each:
   - `writing-epics-stories`: story points use 1, 2, 4, 8, 16, or 32, and anything larger is split. Draft issues in `.agents/plan/` and post them only after the developer approves.
   - `writing-documentation`: avoid jargon.
   - `skill-reviewer` agent: instruction files state rules as terse directives without rationale.
   - `base.md`: never add a `Co-authored-by` trailer unless the developer asks for one.
4. Add `.github/instructions/tara-invariants.instructions.md` with `applyTo: "src/**"` for this repository: never overwrite or delete a file Tara did not generate, keep every write inside the repository and off symlinked paths, fail closed on unparseable input, report errors as one line instead of a traceback, keep the CLI and config backward compatible, and persist tool lists as explicit names.
5. Changelog: Changed entry for the review prompt and the workflow review step.
6. Stage and draft: `feat: require independent review and check project invariants`.

**Review stop.**

### 4. Stop granting a commit tool by default (#50)

1. Test: a fresh `init` does not select the `git` MCP server.
2. Remove `default = true` from the `git` entry in `src/tara/data/mcp/catalog.toml`.
3. Test and add a `tara audit` warning when `.mcp.json` configures the `git` server.
4. Leave existing `.mcp.json` files unchanged.
5. Changelog: Changed entry with the migration note "remove the `git` server from `.mcp.json` or keep it on purpose".
6. Stage and draft: `fix: stop selecting the git MCP server by default`.

**Review stop.**

### 5. Stop overwriting copilot-instructions.md and .mcp.json (#30)

1. Test: `tara init` on a repository with a hand-written `.github/copilot-instructions.md` leaves it unchanged when non-interactive and reports it as skipped.
2. Test: the same for a hand-written `.mcp.json`.
3. Route `core._write` (`src/tara/core.py`) through `generate.write_generated` for markdown and `generate.write_configured` for JSON.
4. A generated file without the marker prompts once in an interactive session. Document that in the changelog.
5. Stage and draft: `fix: never overwrite hand-written instructions or MCP config`.

**Review stop.**

### 6. Report skipped locally modified artifacts (#24)

1. Test: `tara rebuild` on a repository with an edited catalog artifact lists it under "skipped, locally modified".
2. Change `_rebuild_manifest` in `src/tara/cli.py` to collect and print the skipped artifacts. Recording them in the manifest is out of scope.
3. Stage and draft: `fix: report locally modified artifacts that rebuild skips`.

**Review stop.**

### 7. Report library skills that rebuild does not restore (#26)

1. Test: `tara rebuild` with an entry in `.tara/library-skills.json` and the skill folder missing prints a note naming `tara skill sync`.
2. Implement the note in `rebuild`. Running the sync phase inside `rebuild` is out of scope.
3. Stage and draft: `fix: report library skills that rebuild does not restore`.

**Review stop.**

### 8. Strict and atomic configuration (#18, breaking part)

1. Test: an unknown top-level or nested key in `.tara/config.toml` raises `ConfigError` with the key name.
2. Test: the legacy `tool` and `tools` keys still load and migrate, including scalar `tool = "all"` as Copilot plus OpenCode.
3. Set `extra="forbid"` on the config models after the legacy migration runs.
4. Test: a failed write leaves the old `.tara/config.toml` intact and raises `ConfigError`.
5. Write the config atomically: write a temporary file in `.tara/`, then `os.replace` it.
6. Changelog: Changed entry under breaking changes, with the migration step.
7. Stage and draft: `fix: reject unknown config keys and write config atomically`.

**Review stop.**

### 9. Integration lifecycle (#18, remaining items)

Do each item test-first and stage it as its own commit.

1. Rerunning `tara init` without `--integrations` keeps the configured integrations.
2. `tara init --integrations` that drops an integration removes only Tara-owned artifacts, the same as `tara integrations`.
3. Deleting a Copilot prompt or agent prunes its generated Claude or OpenCode copy, keeps hand-written files, and restores a starter command it was shadowing.
4. Integration artifacts are removed only after the new config is persisted.
5. A malformed or unreadable `opencode.json` during removal is reported as an error.

If an item needs the `integrations` service-module refactor from #18 to be done safely, stop and report. Otherwise leave the refactor for 2.x.

**Review stop.**

### 10. Fix the PR #17 review blockers (#56, #60, #61, and the folded items in #18 and #21)

The findings are in `.agents/review/202610062245_pr-17-branch-review.md` and `.agents/review/202610062300_code-quality-and-structure-review.md`.
Make one commit per issue.

1. #56: test that an agent with unparseable frontmatter is skipped and reported by the Claude and OpenCode translators, then make both fail closed.
   Stage and draft: `fix: skip agents whose frontmatter does not parse`.
2. #21 (folded in from #57): test the version lookup without depending on the installed distribution name, then resolve the distribution that provides the `tara` module with `tara-dev` as fallback.
   Stage and draft: `fix: read the version from the tara-dev distribution`.
3. #18 (folded in from #58): test an `[artifacts]` list that spans several lines, then update the table so the file still parses and keeps unrelated content.
   Stage and draft: `fix: keep config.toml valid when updating artifacts`.
4. #60: test that malformed config, settings, and checks files give one error line and exit 1, then add `errors.py` with `TaraError`, a `main()` entry point, and replace both `except Exception` blocks.
   Stage and draft: `fix: report errors as one line instead of a traceback`.
5. #61: one test per fix for the deep review exit code, the dry-run prompt, and the quoted skill key, then the fixes and the dead-code removal.
   Stage and draft: `fix: small correctness fixes from the quality review`.
6. #61 (folded in from #62): test that every bundled catalog file parses and passes the audit rules, then fix the starter commands.
   Stage and draft: `fix: use tara check in starter commands`.
7. Changelog: one Fixed entry per issue.

**Review stop.**

### 11. Governance documents (#38)

1. Add `SECURITY.md` that points to GitHub private vulnerability reporting.
2. Add `docs/support-policy.md` with the supported Tara versions (latest minor of the current major), the supported Python versions (3.12 to 3.14), and the deprecation policy (deprecated flags and keys keep working with a warning for at least one minor release, removed only in a major release).
3. In the same page, state that `tara check` runs the commands in a repository's `.tara/checks.toml`, so it must not be run in an untrusted clone.
4. Link both from the README.
5. (developer) Enable private vulnerability reporting in the repository settings.
6. Stage and draft: `docs: add security, support, and deprecation policy`.

**Review stop.**

### 12. Release pipeline (#22)

1. Extend `.github/workflows/ci.yml` with a test matrix for Python 3.12, 3.13, and 3.14.
2. Add a `build` job that runs `uv build` once and uploads `dist/` as an artifact.
3. Add a `smoke` job that installs the wheel and the sdist in clean environments and runs `tara --version`.
4. Add `.github/workflows/release.yml`, triggered by a `v*` tag. It reuses the built artifacts, generates attestations, publishes to PyPI with trusted publishing (no token), and attaches the artifacts to the GitHub release.
5. Pin every action to a commit SHA, following the `securing-github-actions` skill. Run `uv run pre-commit run --all-files` so `zizmor` and `actionlint` check the workflows.
6. (developer) Add the trusted publisher on PyPI for project `tara-dev`, workflow `release.yml`, environment `pypi`.
7. Stage and draft: `ci: build once, test the Python matrix, publish with trusted publishing`.

**Review stop.**

### 13. (developer) Protect main (#37)

1. (developer) Require a pull request with review, block force pushes and deletion, and require the job names from step 12 as status checks.
2. List the required checks in `.agents/runbooks/release-a-new-version.md`. The agent prepares this edit.

### 14. Set the version to 2.0.0 (#21)

Before this step, a clean agent on a different model reviews the whole codebase against the invariants and the two PR #17 reviews, and files the result in `.agents/review/`.
Stop if it finds a blocker.

1. Set `name = "tara-dev"` and `version = "2.0.0rc1"` in `pyproject.toml`. The CLI command and the import module stay `tara`.
2. Merge the unpublished `[1.1.0]` section of `CHANGELOG.md` into `[Unreleased]`, so 2.0.0 lists every change since 1.0.0.
3. Make a "Breaking changes" list with one migration step per item.
4. Check that the compatibility tests cover `--tool`, `--tools`, `tara tools`, and the legacy config keys.
5. Regenerate the CLI docs and run `uv lock`.
6. Stage and draft: `chore: prepare 2.0.0rc1`.

**Review stop.**

### 15. Release

1. (developer) Open the PR for `fix/stable-2.0.0-blockers` and link #18, #20 (if not closed by #17), #21, #22, #24, #26, #30, #38, #49, #50, #56, #60, and #61 through Development. Merge after review and green checks.
2. Follow `.agents/runbooks/release-a-new-version.md` for `2.0.0rc1`, then for `2.0.0`.
3. Close #33 when the stable release is published.

## Rollback

- A step that breaks the gate: `git restore --staged` and `git restore` on that step's files only, after the developer confirms.
- A broken release: follow the rollback section of `.agents/runbooks/release-a-new-version.md`.
